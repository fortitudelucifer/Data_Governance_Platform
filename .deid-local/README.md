# .deid-local — PHI 去标识本地存储(**开发期过渡态，非生产终态**)

## 这是什么

C-Q1 ①② 拍板(2026-07-26)的落地：真实病人数据的**去标识产物**与
**UID 重映射表**在**开发期**暂放这里。

## ⚠️ 三条铁律

1. **整个目录永不入库。** `.gitignore` 已挡死(`/.deid-local/**`)。里面一旦有
   真实数据就是 PHI，进了公开仓库就是数据泄露且不可撤销。只有本 README 与
   `.gitkeep` 入库(用来固定目录，不含任何数据)。

2. **这是过渡态。** 生产环境去标识与 UID 表都必须在**专用隔离机器 + 加密存储**上。
   本机同时跑开发与去标识、UID 表以本地明文文件夹存放——都只在
   "专用机还被开发占用"的过渡期成立。专用机一旦空出，两者都迁过去。

3. **去标识必须发生在写入对象存储之前。** 文件一旦落进 `backend/storage/assets`，
   PHI 就已经泄露，事后清洗没有意义。`DeidGate`(fail-closed)保证 clinical
   数据在有去标识管线前连上传 URL 都拿不到。

## 目录

- `uid-map/` — UID 一致重映射表(同一 study 恒得同一假 ID，确定性去标识)。
  表本身是 PHI。生产迁专用加密存储。

## 现状

`DeidPipeline` 尚未实现(D-1 欠账)。当前开发全用公开去标识数据集，
这个目录**还不会有任何内容**——它是接真实临床数据前就位的容器，不是现在就用的。
